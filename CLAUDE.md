# CLAUDE.md

## Project Overview

beepsboops is a Pocket Operator-inspired 16-step web sequencer. It runs entirely in the browser with no backend.

## Commands

- `pnpm dev` — start dev server
- `pnpm build` — type-check (`tsc`) then production build (`vite build`)
- `pnpm preview` — serve the production build locally
- `node scripts/generate-samples.mjs` — regenerate drum WAV files in `public/samples/`

## Architecture

Three layers with strict dependency flow: **audio → sequencer → ui**

### Audio Layer (`src/audio/`)
Web Audio API engine. The scheduler uses the **Two Clocks pattern** — a `setTimeout` loop (25ms interval) schedules notes using `AudioContext.currentTime` (hardware clock) with a 100ms lookahead window. This is critical for jitter-free timing. Each note trigger creates a disposable `AudioBufferSourceNode`.

Audio graph: `BufferSource → per-track GainNode → master GainNode → destination`

### Sequencer Layer (`src/sequencer/`)
State model: 8 tracks × 16 steps. Each track has a boolean pattern array and a pitches array (semitone offsets for melodic tracks). State is a plain mutable object — no state management library. Persistence via `localStorage`.

### UI Layer (`src/ui/`)
Thin DOM manipulation. Each module exports an `init()` function that creates elements and binds event listeners. The playhead uses `requestAnimationFrame` polling the scheduler's `notesInQueue` array for visual sync.

## Key Conventions

- **No framework** — vanilla TypeScript, direct DOM manipulation. Keep it this way.
- **Single `style.css`** — all styles in one file with CSS custom properties for theming.
- **Samples are WAV files** in `public/samples/`, generated by `scripts/generate-samples.mjs`. They are synthesized (sine sweeps, noise bursts), not recorded.
- **Mobile-first** — `touch-action: manipulation` everywhere, `pointerdown` events (not `click`), `100dvh` layout.
- **No `click` events on interactive elements** — use `pointerdown` for zero-latency touch response.
- **Audio context must be resumed on user gesture** — `ensureAudioReady()` in `src/audio/context.ts` handles this including the iOS Safari silent buffer trick.

## Testing

After every change, run the Playwright test suite and verify layout visually:

1. `pnpm exec playwright test` — run all tests
2. Review any screenshot diffs or failures before considering the task done
3. If no tests cover the changed area, write a Playwright test for it
4. For layout changes, use `page.screenshot()` and inspect the result — check mobile viewport (`375×667`) and desktop (`1280×800`)

Add `pnpm exec playwright test` to the Commands section if not already set up, and install via `pnpm exec playwright install` if browsers are missing.

## Gotchas

- `AudioBufferSourceNode` is single-use — create a new one per trigger, never reuse.
- The scheduler's `notesInQueue` array is shared between the scheduler (producer) and playhead (consumer) — the playhead shifts entries off as it renders them.
- BPM changes take effect on the next scheduler tick (within 25ms + lookahead, so effectively instant).
- The synth track supports per-step pitch via `playbackRate` — changing pitch also changes duration (PO-style).
